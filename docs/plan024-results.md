# Проверка исправлений SOV — PLAN-024

4 октября 2026 года использован отдельный временный пробный Git-проект на Linux с Python `unittest`, OpenCode 1.18.33 и внешним закреплённым checkout SOV `7d7526d`. Рабочий проект SOV и действующие целевые проекты не переключались. Пробные пути находились в `/tmp/opencode/plan024/`; эти локальные файлы не входят в публикацию SOV. Проба без Git remote: проверки слияния PR и очистки worktree после сохранения незакоммиченного результата здесь не проводились. Ранее проверенные публикации PR описаны в [PLAN-013](e2e-results.md), параллельные писатели — в [PLAN-020](parallel-state-results.md); они не подменяют сценарии ниже.

Для подтверждённого однозначного бага без отдельной спецификации и для бага с опубликованным правилом агент выбрал `sov-plan`; при конфликте предложенного `2*n` с опубликованным `abs(n)*2` остановил переход к реализации и назвал `sov-spec → sov-review-spec`; при гипотезе без воспроизведения вернул работу к `sov-research`. Он также отказался начинать `sov-implement` без пригодного `plan.md`. **Это проверка выбора маршрута по инструкциям, не фактическое изменение статуса `blocked` и не сквозное выполнение веток остановки.**

## Установка и границы проверки

- Из checkout по commit `7d7526d` через `build-candidate.sh` собран `sov-state 0.1.0 (protocol v:1)`; кандидат проверен, затем опубликован единым путём `/tmp/opencode/plan024/sov-7d7526d/bin/sov-state`. Один бинарник прочитал разные `ROADMAP.md` и вернул разные revision для двух проектов с `state-dir=/tmp/opencode/plan024/project-a/.sov` и `.../project-b/.sov`. Для каждого проекта создан собственный `.roadmap.lock`; no-op `commit` с прежним revision дал `changed:false`, содержимое не менялось. В проекте A `.sov/` исключена из Git (`git check-ignore .sov/ROADMAP.md`). Работу независимых параллельных координаторов заново не включали.
- В A конфигурация и три проектные команды закоммичены до проверки worktree. `opencode debug config` из основной копии и worktree обнаружил `/sov`, `/sov-feature`, `/sov-bug`, путь к закреплённым скилам и разрешения `external_directory`. Реальный агент из worktree прочёл внешний `templates/task.md`, общий локальный артефакт, выполнил `--version` и `read --state-dir` через зафиксированный бинарник; маршруты TASK-001 и TASK-002 подтвердили запись общего состояния и артефактов через OpenCode. Во втором проекте B проверен тот же бинарник с отдельным состоянием; обнаружение команд OpenCode в B не проверялось.
- Пробный TUI-сеанс завершён и остановлен. В отдельной проверке безопасного обновления запуск сборки нового кандидата с недоступным Go завершился ошибкой (`go: command not found`), после чего установленный бинарник по старому пути по-прежнему вернул `v:1` и успешно прочёл состояние B, кандидат не появился. Это проверяет отказ до переключения; **успешная замена версии и возобновление старой живой сессии не моделировались**. В активных проектах и глобальной конфигурации OpenCode ничего не менялось.

Проверены фактические артефакты `task.md`, `research.md`, `plan.md`, `checks.md`, `review.md` обеих пробных задач, `git diff --check` и обязательные Python-тесты на конечных diff. Код CLI и протокол не менялись, поэтому `go test -race ./...` и параллельный сценарий PLAN-020 не повторялись. Выводы относятся только к указанной версии, окружению и исполненным сценариям.
