# Сквозная проверка SOV — PLAN-013

3 октября 2026 года маршруты SOV проверены на **отдельном закрытом пробном репозитории**, а не на коде этого проекта. Проверка выполнялась по инструкциям скилов с независимыми субагентами для обязательных ревью. Команды OpenCode запускались дополнительно для проверки подключения и выбора источника задач. Пробный проект использовал файловый список `.sov/ROADMAP.md`, Python `unittest`, отдельные Git worktree и PR в `main`.

| Сценарий | Фактический результат |
| --- | --- |
| Подготовка требований и зависимая реализация | Требования `greet` опубликованы в PR #1 после независимого ревью и показа человеку; TASK-002 не назначалась до подтверждения слияния. Код с четырьмя успешными тестами и независимым ревью опубликован в PR #2. |
| Уточнение требований вместе с реализацией | Пробелы по краям имени: `sov-review-spec` проведён **до** написания кода; уточнение и код опубликованы вместе в PR #2. До слияния уточнение оставалось только в ветке задачи, не в `origin/main`. |
| Исследование без исправления | Для пробной ошибки `increment(-1)` зафиксированы воспроизведение, причина (`abs(value)`) и предложение решения в TASK-003; код не менялся, опубликование не требовалось. |
| Исправление ошибки, остановка и продолжение | В TASK-004 регрессионный тест сначала провалился (1 из 6); статус оставлен `blocked`, PR не создавался. После сверки сохранённых артефактов и worktree задача продолжена с исправления, все 6 тестов прошли, независимое ревью и слияние PR #5 подтверждены. При повторной сверке уже слитого PR новый PR не создан. |
| Установка, команды и данные | OpenCode загрузил `sov-orchestrator`; `/sov-feature` завершила только обсуждение без файлов, `/sov` сообщила об отсутствии поддержки CLI и предложила выбор файлового источника, `/sov-bug` из пробной worktree прочитала общий шаблон и артефакт основной копии. `.sov/` исключён из Git; после слияния рабочие копии задач удалены без потери общих артефактов. |

Обнаруженное расхождение при первой установке: наличие скила в `skills.paths` **не давало** OpenCode доступа к другим файлам установленного SOV во внешнем каталоге; вызов завершился отказом `external_directory`. Пробный проект получил узкое разрешение на этот каталог через отдельный PR #3, проверка из основной копии и worktree прошла. Инструкция установки в [README](../README.md#установка-и-обновление-в-существующем-проекте-для-агента) уточнена. В пробном проекте также уточнено правило проверок: `NO TESTS RAN` при публикации одних требований не засчитано как успешное тестирование; для задач с кодом тесты выполнялись реально.

Пробный PR #4 намеренно добавил воспроизводимый дефект и опубликованное требование для проверки маршрутов исследования и исправления. У проекта не было обязательных GitHub checks; перед слиянием проверялись состояние PR, его файлы и локальные тесты. Проверки путей OpenCode проводились отдельными новыми запусками `opencode run`; полный многошаговый маршрут через **один** интерактивный вызов `/sov` не запускался. Это граница полученных свидетельств, а не подтверждение такого режима. Полные локальные записи и ссылки на закрытые пробные PR сохранены в заметке PLAN-013 в Obsidian.
