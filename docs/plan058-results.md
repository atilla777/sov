# PLAN-058 — проверка первой установки и обновления

2026-10-07. На временном Git-проекте с собственным bare `origin`, отдельной `.sov/` и worktree проверен переход между двумя неизменяемыми checkout SOV: `a849ddd10e5576e8013137215e1ea0e5454297d5` (первая установка) → `b6a6e8b32f04df3f3e9527bed8ae7db0dc402279` (ручное обновление). Действующие подключения не менялись. Воспроизводимый сценарий: `mise exec go@1.25.4 -- python3 tests/plan058_trial.py`; сценарий удаляет временный проект по завершении. Использованы OpenCode 1.18.33, Go 1.25.4 и Git.

## Фактические действия и наблюдения

1. В пробном проекте заранее существовали `AGENTS.md` с пользовательским разделом и индексы `rules/index.md`, `docs/index.md`. По [инструкции](install-filesystem-tasks.md#первое-подключение) добавлены проектная конфигурация OpenCode, шесть команд, два агента, игнорируемая общая `.sov/` и раздел подключения с SHA, абсолютными путями, `/sov`, источником задач, моделями, проверками и порядком публикации. Пользовательский раздел остался на месте; `git check-ignore .sov/tasks/0001-probe/task.yaml` подтвердил исключение состояния. В основной копии из Go-исходников старого checkout выполнены `go test -race ./...` и `go build` кандидата, бинарник установлен атомарной заменой.
2. `sov-task create` создал карточку `0001`; `validate`, `list`, `show 0001`, `list-completed` из основной копии и worktree показали один и тот же источник (валиден, одна активная карточка, завершённых нет). `opencode debug config` в обеих копиях показал закреплённый `skills.paths` и шесть команд; `opencode debug agent sov-standard` и `sov-advanced` показали Luna и Sol; шаблон и инструкция оркестратора доступны. Отдельной `.sov/` в worktree нет. Пробная конфигурация опубликована только в локальный bare `origin/main`.
3. Перед обновлением сохранена копия состояния, выполнены `go test -race ./...`, сборка кандидата из нового checkout и его `validate` на прежней `.sov/`. При намеренно добавленной пользовательской строке в одноимённую команду проверено несовпадение с исходником старого выпуска: замена **не выполнялась**, карточка оставалась видимой. После явного разрешения конфликта внутри фикстуры обновлены пути, команды, агенты и бинарник; пользовательский раздел `AGENTS.md` сохранился. Новая конфигурация опубликована в локальный bare `origin/main`, worktree обновлена; повторены проверки обеих копий, байтовое совпадение карточки с копией и сверка SHA remote.
4. После переключения запущены новые процессы `opencode run --dir <worktree> --agent sov-standard --model openai/gpt-6-luna` и аналогичный вызов `sov-advanced` с `openai/gpt-6-sol`: получены диагностические ответы `STANDARD-OK` и `ADVANCED-OK`. Это реальные вызовы моделей из пробной worktree, но **не** вызовы субагентов основным агентом через `task`. Проверка конфигурации и задач выполнялась также из основной копии; живой модельный вызов из неё отдельно не выполнялся.
5. Отдельная фикстура старого `ROADMAP.md` без каталогов файловых задач и несовпадающий файл команды распознаны как условия остановки до изменения данных. Это проверка условия в сценарии, **не** запуск `sov-update` реальным агентом при несовместимом хранилище и не проверка остановки действующих OpenCode-сеансов. Работающие старые писатели, восстановление после частичного переключения, реальные пользовательские решения и GitHub/CI не испытывались.

Сценарий окончен выводом `FIRST INSTALL ... OK`, `LIVE MODEL: sov-standard ...`, `LIVE MODEL: sov-advanced ...`, `UPDATE ... OK`, `STOP ... OK`. Дефектов инструкции в проверенной области не обнаружено. Состояние теста и пути временного проекта не публикуются; публикуются только сценарий и результаты.
