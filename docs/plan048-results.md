# PLAN-048 — интерактивная проверка текущего SDLC

2026-10-07 проверен **реальный OpenCode CLI** 1.18.33 (`opencode run` с `--command`, продолжением сессии и отдельными вызовами проектных субагентов) на двух изолированных Git-проектах под `/tmp/opencode/plan048-trial/`. Это не TUI-сеанс: ответы человека получены в основном диалоге и переданы в продолженную OpenCode-сессию; ни ответ пользователя, ни проверка reviewer не подменялись скриптовой фикстурой. Первый проект имеет собственные `.sov/` и bare `origin.git`, второй — отдельные `.sov/` и `review-origin.git`. Действующие подключения, включая moy, не менялись.

## Подключение и повторение

- Неизменяемый checkout SOV: `f74d8c4b03a488871232e78868581fb3962b29c5`; Python с PyYAML 6.0.3, CLI `cli/sov-task/sov_task.py` **этого исторического выпуска** с явным `--state-dir` основной копии. Пробная установка по действовавшей тогда редакции [инструкции](install-filesystem-tasks.md): `opencode.json` указывает на каталог `skills/` этого checkout, в Git проекта добавлены пять файлов `.opencode/commands/sov*.md` и два проектных агента; `.sov/` исключён из Git. Модели `sov-standard = openai/gpt-6-luna`, `sov-advanced = openai/gpt-6-sol` доступны в `opencode models openai` и подтверждены `opencode debug agent` из основной копии и worktree. `opencode debug config` в обеих копиях показывает все пять команд и путь скилов; `sov-task validate` и `list` из обеих копий читали один пустой общий источник. Конфигурация проекта опубликована только в пробный remote (`6610f48`). После изменения конфигурации запускались новые OpenCode-процессы.
- Для повтора: создать отдельные Git-проект и локальный bare-remote, подключить **закреплённый** SOV по инструкции, создать четыре пустых каталога `.sov/tasks/`, `claims/`, `completed/`, `archive/`, закоммитить конфигурацию, проверить её из новой worktree и запускать OpenCode оттуда. Команды: `opencode run --dir <worktree> --model openai/gpt-6-sol --command sov-feature --auto '<поручение только на Spec>'`, затем `opencode run --dir <worktree> --session <ID> --model openai/gpt-6-sol --auto '<ответ человека и продолжение>'`; после подтверждённой публикации `opencode run --dir <worktree> --model openai/gpt-6-sol --command sov-decompose --auto '<явный запрос с путём опубликованной Spec>'`, далее `--command sov` с ID подготовленной задачи. Опция `--auto` разрешала запросы инструментов в этих **изолированных** проектах; она не является свидетельством ответа человека. Для проверки каждого перехода использовать `sov-task --state-dir <main>/.sov validate/list/list-completed/show/show-completed`, `git ls-remote origin refs/heads/main`, полный diff и артефакты задачи. Реальные ID сессий сохранены ниже, результаты проверяемы до удаления временного стенда.

## Второй проект: честная проверка блокирующего замечания

Поскольку естественное ревью первой реализации прошло без замечаний, цикл возврата проверен **отдельной контролируемой fault-injection пробой**, а не представлен как найденный дефект исходного кода. Второй проект клонирован с корректной опубликованной реализацией; его отдельный remote и state-dir не пересекаются с первым. Задача `0001` требует промежуточный черновик, объективную блокировку, исправление и новое ревью.

1. Реальный `/sov` (`ses_ee9e29e8bffeyM4U4F3noY6G5Q`) вызвал отдельный `sov-plan` (Luna). План зафиксировал корректную базу `611152f19593e8d893e21b2ac494e1f7fb4acb4f` (3/3 теста) и точный инъецируемый дефект: ранний `return` при пустой строке до `print(text)`.
2. Следующий `/sov` (`ses_ee9dd7c4affeqH4gADvEMMBV95`) вызвал отдельный `sov-implement` (Sol) для **временного** черновика. На нём `python3 -m unittest discover -v` дал **2/3**, только проверка пустой строки упала (`stdout ""` вместо `"\n"`). Новый независимый `sov-review-implementation` (Sol) самостоятельно повторил тест, проверил требования и инженерное качество, записал R1/F1 в `review.md` как блокирующее замечание к временному черновику. Публикации не было, claim освобождён.
3. Продолжение `/sov` (`ses_ee9d9bb22ffeJy4cChiKA7mbUe`) вызвало **другого** `sov-implement` (Sol), удалившего ранний выход, сохранившего старые тесты и добавившего отдельный тест простого ASCII-текста. Новый независимый reviewer (Sol) самостоятельно проверил итог **4/4 теста**, обе оси и закрытие F1 в записи R2; `git diff --check` успешен. Полный итоговый diff содержит **только новый тест**: искусственно сломанный черновик не попал в публикацию. Прямой push в отдельный локальный `review-origin.git` дал `465754c7d95c8ad14aa1c885e02a47fc3e0403dd`, remote SHA подтверждён **до** `complete 0001`. `show-completed` и `validate` подтверждают архив и корректное состояние.
