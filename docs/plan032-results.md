# PLAN-032 — оценка сценария MOY-019

Основание: только чтение локальных `MOY-019/task.md` и `checks.md` в moy и контракта закреплённого SOV `af36f70`. MOY-019 последовательно создала запись, захватила её, подтвердила опубликованный SHA и CI, записала `done`, перенесла строку в ARCHIVE. Артефакты подтверждают эти этапы, но не содержат полного журнала вызовов CLI: **точное** число реальных вызовов первоначальной сессии не измерено. Одноразовая ошибочная проверка ссылок была дефектом документальной проверки, а не файлового протокола; итоговая проверка обнаружила все 44 существующие ссылки. Результат одноразового скрипта следует проверять до записи в `checks.md`.

| Типовой этап чтения | До, установленный SOV 0.3.0 | После отдельного подключения `sov-tasks-view` |
| --- | --- | --- |
| Просмотр по ID / поиск владельца / очередь | Не менее 2 вызовов `sov-state read*`, декодирование и ручная проверка двух таблиц, отдельный разбор для ответа. | 1 вызов агента `get` / `owner` / `queue`; 0 ручных декодирований и сборок, 4 внутренних read CLI за попытку; внешние условия остаются агенту. |
| Диагностика | Агент проверяет оба файла, связи и возможность промежуточного дубликата. | 1 вызов `validate`, 0 ручных разборов, диагностика каждого файла с линиями; до 3 попыток по 4 внутренних чтения при конкуренции. |
| Создание, захват, `done`, архивация | Для каждого изменения свежие чтения, смысловая проверка, полные отдельные входные файлы и CAS; при архивировании два файла. | **Без изменения:** read-only этап не экономит записывающие вызовы и не переносит проверку SHA/CI или захвата в инструмент. |

Показатель выигрыша при повторе сценария: журналируйте количество **вызовов агента** и отдельно внутренних запусков CLI, число ручных декодирований/сборок полных файлов, места ручного выбора после конфликта/потери ответа. Не сравнивайте один вызов агента с четырьмя внутренними чтениями как ускорение времени: цель первого этапа — проверяемость и уменьшение ручной работы чтения. Для подсчёта фактического «до» нужен журнал вызовов исходной сессии, которого в артефактах нет. Экономию на операциях записи можно оценивать только после отдельного решения и реализации высокоуровневой записи.

Проверка чтения: отдельные фикстуры с повреждённой очередью и архивом, конфликтом revision двух сессий, повторным чтением после потерянного ответа, отменённой зависимостью, циклом, стабильным и расходящимся дубликатом; чтение реального состояния moy выполняется без записи, **не** является подключением нового выпуска к moy.
