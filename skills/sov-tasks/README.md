# `sov-task` — CLI скила `sov-tasks`

Исходники Go CLI и тесты поставляются вместе с [инструкцией скила](SKILL.md). Файловый контракт: [SOV Tasks](../../docs/specs/filesystem-tasks.md). Для сборки требуется Go 1.25.4 (или совместимая более новая версия); для работы бинарника Go и Python не нужны.

Из этого каталога: `go test -race ./...`; `go build -o /tmp/sov-task .`. При установке соберите кандидат из закреплённого checkout в отдельный файл **в каталоге конечного бинарника**, проверьте его на изолированном хранилище и только затем атомарно замените бинарник при остановленных писателях. Абсолютный путь бинарника и абсолютный `state-dir` основной копии задаются в правилах проекта; из worktree используются те же пути.

Пример: `/abs/sov-task --state-dir /abs/project/.sov validate`. Команды: `list`, `list-ready`, `show <id>`, `list-completed`, `show-completed <id>`, `create --file <yaml> --slug <name>`, `claim <id> [--owner ...]`, `claim-next [--owner ...]`, `release <id> [--owner ...]`, `complete <id> [--owner ...]`, `validate [id]`.

Ответы — JSON; ошибки — JSON на stderr и exit 2. `validate` при ошибках целостности возвращает `valid:false` на stdout с exit 2; `claim` при неготовой задаче даёт `status:not_ready`, `claim-next` без доступных задач — `status:no_ready_tasks`, оба с exit 0. Завершённые карточки возвращаются полностью и только при согласованных marker, архиве и отсутствии claim.

Создание под `flock` выделяет ID после максимума в задачах, архиве, маркерах и claims. Claim создаётся атомарным `mkdir`; диагностический `owner` не служит lease или подтверждением живости сеанса. `complete` выполняет marker → перенос всего каталога задачи → удаление claim. Если действие прервано, `validate` выявляет известные промежуточные состояния; повтор `complete` при прежнем собственном claim завершает перенос. Публикацию результата и право на завершение проверяет агент, не CLI. Состояние рассчитано на одну локальную ФС с атомарными `mkdir`/`rename` и `flock`; `validate` не проверяет полный граф зависимостей.
