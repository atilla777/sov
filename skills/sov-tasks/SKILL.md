# Учёт задач SOV

Этот скил — единственный интерфейс к общему списку задач. Оркестратор и скилы шагов запрашивают у него задачу и состояние, но не читают и не редактируют источник списка напрямую. Здесь ведутся только идентификатор, название, статус, назначение, зависимости, порядок и признак необходимости публикации. Запрос, маршрут, причины блокировки, проверки и подтверждение публикации сохраняются оркестратором в `.sov/tasks/<task-id>/task.md`, а не копируются как второй общий статус. Артефактами и worktree этот скил не управляет.

## Источник и адресация

1. Получи абсолютный путь к **основной** папке проекта и настройку источника из его `AGENTS.md` / применимых правил. Не выводи общую папку из текущего каталога worktree. Для начальной реализации поддерживается явно выбранный файловый источник `<основная папка>/.sov/ROADMAP.md`. Если источник не выбран, согласуй его прежде, чем читать или создавать список. При отсутствии файла для выбранного файлового источника предложи инициализацию из [`templates/ROADMAP.md`](../../templates/ROADMAP.md) с согласованным префиксом ID; не объявляй пустую очередь, пока список не создан.
2. CLI поддерживается только после отдельной реализации подключения и проверки доступности. Найденный в системе CLI сам по себе не является источником SOV. Если проект выбрал неподдерживаемый источник, сообщи о препятствии и предложи явно выбрать файловый; не переключайся молча и не создавай параллельный список.
3. Передай вызывающему агенту запись задачи и абсолютный путь `<основная папка>/.sov/tasks/<task-id>/`. Папку при начале сохраняемой работы создаёт оркестратор. Стабильный ID — ключ к папке и внешним ссылкам; после создания его нельзя переименовывать или выдавать повторно.

## Формат файлового списка

Формат и пустой образец — в [`templates/ROADMAP.md`](../../templates/ROADMAP.md). В поле `Следующий ID` записан очередной свободный номер с постоянным префиксом проекта; новые задачи добавляются **в конец** таблицы, после чего номер увеличивается. Удаление, отмена или завершение задачи не освобождают ID. Физический порядок строк определяет очередь; не сортируй таблицу при редактировании. ID уникален, ID и название непустые. Статус — ровно один из `planned`, `in_progress`, `blocked`, `done`, `cancelled`; исполнитель — устойчивый идентификатор агента/сессии или `—`; зависимости — уникальные ID через запятую либо `—`; публикация — `yes` или `no` (определяется поручением и правилами проекта при создании). Не подменяй признак публикации статусом PR.

Перед любой выдачей, выбором и изменением проверь список: единственность ID, отсутствие повторяющихся строк, номер `Следующий ID` больше всех уже выданных номеров с тем же префиксом, допустимость полей, ссылки зависимостей на существующие задачи, отсутствие зависимости от себя и циклов. При нарушении не выбирай и не меняй задачи: сообщи конкретные строки и попроси исправить состояние. При записи перечитай актуальный файл непосредственно перед правкой, повтори проверку и после правки проверь его снова; при неожиданном изменении не перезаписывай чужую работу. Параллельное конкурентное назначение несколькими координаторами не поддерживается.

## Операции

- **Получить**: по ID верни все поля строки, её место в очереди, а также вычисленную доступность и причину недоступности. При отсутствии ID явно сообщи об этом; не выдавай новый ID вместо отсутствующего.
- **Создать**: уточни название, необходимость публикации и зависимости; убедись, что ID зависимостей существуют и нет цикла. Возьми `Следующий ID`, добавь строку с `planned`, исполнителем `—`, выбранными зависимостями и публикацией; увеличь номер. Верни созданный ID и путь к папке артефактов, не создавая саму папку. Новые задачи реализации, зависящие от подготовки требований, остаются `planned` до подтверждённой публикации требований.
- **Выбрать следующую**: просматривай строки по порядку и верни первую задачу со статусом `planned`, исполнителем `—`, зависимостями только в `done` и выполненными условиями начала работы (включая опубликованные требования для разработки). Зависимость `cancelled` **не** выполнена; `blocked`, `planned` и `in_progress` также не выполнены. Если нет доступной, сообщи, пуст ли список либо какие зависимости, назначения или условия мешают; не снимай блокировки для продолжения работы.
- **Назначить / начать**: назначай доступную `planned` задачу названному исполнителю и одновременно переводи в `in_progress`. Для явно указанного ID применяй те же условия начала, что для выбора следующей. Не забирай задачу с другим исполнителем, даже если сессия оборвалась; смена исполнителя или освобождение назначения требует явного решения с фиксацией причины в `task.md`. Если уже назначена тому же исполнителю, верни текущее состояние без повторного назначения.
- **Обновить**: меняй только явно запрошенные поля после проверки текущего статуса и последствий для зависимых задач. Добавление зависимости не должно создавать цикл или делать текущую работу недопустимой без решения оркестратора. При `blocked` сохраняй исполнителя и требуй от оркестратора указать причину и условие снятия блокировки в `task.md`; возвращай в `in_progress` только после устранения препятствия. `cancelled` не переводится в `done` автоматически, а отменённые зависимости требуют отдельного решения. `done` требует достигнутого результата, обязательных проверок и отсутствия блокирующих замечаний; для строки с `Публикация = yes` дополнительно проверь подтверждённое слияние PR в целевую ветку по сведениям оркестратора (`task.md` и фактическое состояние GitHub). Созданный PR, push ветки и готовность к слиянию недостаточны. Если проект согласовал иной маршрут публикации, противоречащий требованию PR в спецификации SOV, не отмечай задачу `done` без разрешения этого противоречия.

После каждого изменения верни вызывающему агенту прежнее и новое состояние, ID, путь артефактов и результат проверки списка. При ошибке записи не утверждай, что переход состоялся; перечитай фактическое состояние перед повтором.

## Самопроверка сценариев

На копии образца списка или мысленно пройди переходы перед использованием в новом проекте: `planned` без зависимостей → назначена → `in_progress`; назначенная другому исполнителю не перехватывается; `planned` с `done`-зависимостью доступна, с `cancelled` или `blocked` — нет; пустой список и список без доступных задач дают разные причины; повторный ID, отсутствующая зависимость, цикл и преждевременный `done` при `Публикация = yes` отклоняются. При наличии проекта с фактическим списком не заменяй его образцом ради проверки.
