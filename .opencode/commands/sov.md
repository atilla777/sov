---
description: Передать поручение оркестратору SOV или продолжить текущую задачу
---

Сначала проверь, что текущий проект подключён к SOV: его правила указывают закреплённую версию ресурсов, их пути и работающий источник задач, а доступный `sov-orchestrator` относится к этой версии. Глобальная видимость команды не доказывает подключения. При отсутствии подключения или конфликте версий сообщи о препятствии, не выбирай задачи. Затем используй скил `sov-orchestrator` как основной агент для этого поручения; если скил недоступен, сообщи об этом вместо имитации его работы.

Запрос пользователя (может быть пустым):

<request>
$ARGUMENTS
</request>

При указанном ID проверь назначение и состояние задачи. При пустом запросе или просьбе продолжить без ID сначала через `sov-tasks` найди незавершённые задачи устойчивого исполнителя из правил проекта: одну продолжи (при `blocked` сообщи препятствие), при нескольких запроси ID, при нуле выбери первую доступную `planned`. Это правило действует и в новой сессии после перезагрузки: не опирайся на память прежнего диалога. Для файлового источника используй только проверенный `sov-state` через `sov-tasks`; до подтверждения назначения не начинай работу, при конфликте пересмотри выбор, при потере ответа прочитай фактическое состояние, а не повторяй запись вслепую. Новый запрос без ID обрабатывай как отдельное поручение. Определи результат и границы по запросу, состоянию задачи и правилам проекта.
