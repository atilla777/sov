# sov-state

Исходники вспомогательной CLI SOV версии **0.3.0**, протокол JSON **v:1**. Она выполняет байтовые `read`/`commit` существующего `.sov/ROADMAP.md`, `read-archive` существующего `.sov/ARCHIVE.md` и условный `archive` обоих файлов на Linux и локальной ФС. Команда `sov-state session-id` без флагов возвращает JSON `{"v":1,"status":"ok","resource":"SESSION","session_id":"<UUID v4>"}` из системного генератора случайных чисел; она не создаёт файлы и не регистрирует захват задачи. CLI не анализирует Markdown и не заменяет скил `sov-tasks`: атомарная проверка владельца/UUID выполняется инструкцией скила поверх условной записи байтов. Порядок подготовки общего бинарника и постоянного mutex описан в [инструкции подключения](../../README.md#подготовка-общего-бинарника-sov-state-linux); обновление старого формата списка — [отдельный этап](../../docs/parallel-activation.md) с остановкой писателей. Параллельный сценарий одного ROADMAP проверен в [PLAN-020](../../docs/parallel-state-results.md); включение в установленном проекте выполняется [отдельно](../../docs/parallel-activation.md).

Исходный контракт `read`/`commit` описан в [историческом проекте CLI](../../docs/shared-state-cli-proposal.md#2-предлагаемый-контракт-cli). `read-archive --state-dir <абсолютный путь>` возвращает содержимое и revision существующего архива, `resource:ARCHIVE.md`. Команда `archive --state-dir <путь> --expected <revision ROADMAP> --input <новый ROADMAP> --archive-expected <revision ARCHIVE> --archive-input <новый ARCHIVE> [--lock-timeout 5s]` под тем же mutex проверяет оба revision, публикует целый архив, затем целый ROADMAP. Успех возвращает оба revision (`revision` и `archive_revision`); конфликт любого файла — exit 10, `resource` указывает конфликтующий файл. Ошибка после публикации архива может возвращать `may_have_committed:true`; при потере ответа следует перечитать оба файла и восстановить перенос по [инструкции `sov-tasks`](../../skills/sov-tasks/SKILL.md#архивация-терминальных-строк). Пара файлов **не атомарна для читателей**: при архивировании строка может временно совпадать со строкой ROADMAP, при офлайн-обновлении формата файлов временно различается схема таблиц. Восстановление выполняется при остановленных писателях. CLI не проверяет смысл переноса или формат. Отсутствующий архив — ошибка, он не создаётся CLI. Входные файлы не могут совпадать друг с другом, с файлами состояния или mutex. Команда `--version` выводит JSON с `message: "sov-state 0.3.0 (protocol v:1)"`. Успех чтения пустого файла возвращает `content_base64: ""`.

Для разработки требуется Go 1.25.4 или совместимая более новая версия. Из этой папки: `go test -race ./...`; сборка: `go build -o /tmp/sov-state .`. Из корня SOV на собранном бинарнике выполняются [`tests/parallel_state_trial.py`](../../tests/parallel_state_trial.py) и [`tests/session_claim_trial.py`](../../tests/session_claim_trial.py): последняя моделирует четыре сеанса, захват, передачу и миграцию в отдельном временном каталоге, а не в подключённом проекте. Для установки из закреплённой версии SOV используйте `sh build-candidate.sh /абсолютный/путь/к/каталогу/.sov-state-next` при существующем каталоге назначения: скрипт не заменяет работающий бинарник, публикует целого проверенного кандидата и очищает временный файл при ошибке. После проверки кандидата отдельно публикуйте его в общий путь по инструкции выше. При смене версии CLI обновляйте ожидаемый номер версии в скрипте вместе с исходниками. Не запускайте `commit` для проекта, где остальные писатели ещё редактируют ROADMAP напрямую.
