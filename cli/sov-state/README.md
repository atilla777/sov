# sov-state

Исходники вспомогательной CLI SOV версии **0.2.0**, протокол JSON **v:1**. Она выполняет байтовые `read`/`commit` существующего `.sov/ROADMAP.md`, `read-archive` существующего `.sov/ARCHIVE.md` и условный `archive` обоих файлов на Linux и локальной ФС. CLI не анализирует Markdown и не заменяет скил `sov-tasks`. Порядок подготовки общего бинарника и постоянного mutex описан в [инструкции подключения](../../README.md#подготовка-общего-бинарника-sov-state-linux); новый файловый маршрут `sov-tasks` требует явного переключения писателей в целевом проекте. Параллельный сценарий одного ROADMAP проверен в [PLAN-020](../../docs/parallel-state-results.md); включение в установленном проекте выполняется [отдельно](../../docs/parallel-activation.md).

Исходный контракт `read`/`commit` описан в [историческом проекте CLI](../../docs/shared-state-cli-proposal.md#2-предлагаемый-контракт-cli); новые команды доступны только в версии 0.2.0. `read-archive --state-dir <абсолютный путь>` возвращает содержимое и revision существующего архива, `resource:ARCHIVE.md`. Команда `archive --state-dir <путь> --expected <revision ROADMAP> --input <новый ROADMAP> --archive-expected <revision ARCHIVE> --archive-input <новый ARCHIVE> [--lock-timeout 5s]` под тем же mutex проверяет оба revision, публикует целый архив, затем целый ROADMAP. Успех возвращает оба revision (`revision` и `archive_revision`); конфликт любого файла — exit 10, `resource` указывает конфликтующий файл. Ошибка после публикации архива может возвращать `may_have_committed:true`; при потере ответа следует перечитать оба файла и восстановить перенос по [инструкции `sov-tasks`](../../skills/sov-tasks/SKILL.md#архивация-терминальных-строк). Пара файлов **не атомарна для читателей**: архивная строка может временно совпадать со строкой ROADMAP; она никогда не должна исчезнуть из обоих файлов. CLI не проверяет смысл переноса. Отсутствующий архив — ошибка, он не создаётся CLI. Входные файлы не могут совпадать друг с другом, с файлами состояния или mutex. Команда `--version` выводит JSON с `message: "sov-state 0.2.0 (protocol v:1)"`. Успех чтения пустого файла возвращает `content_base64: ""`.

Для разработки требуется Go 1.25.4 или совместимая более новая версия. Из этой папки: `go test -race ./...`; сборка: `go build -o /tmp/sov-state .`. Для установки из закреплённой версии SOV используйте `sh build-candidate.sh /абсолютный/путь/к/каталогу/.sov-state-next` при существующем каталоге назначения: скрипт не заменяет работающий бинарник, публикует целого проверенного кандидата и очищает временный файл при ошибке. После проверки кандидата отдельно публикуйте его в общий путь по инструкции выше. При смене версии CLI обновляйте ожидаемый номер версии в скрипте вместе с исходниками. Не запускайте `commit` для проекта, где остальные писатели ещё редактируют ROADMAP напрямую.
