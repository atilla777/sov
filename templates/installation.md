# Подключение SOV в <название проекта>

Локальная запись установки в `<абсолютный путь к основной копии>/.sov/installation.md`.
Используется при установке и ручном обновлении, но не требуется оркестратору
при обычном `/sov`. Этот файл исключён из Git вместе с `.sov/`; он не заменяет
проектные `AGENTS.md`, `rules/` и `docs/`. Заполняй только проверенными значениями,
не храни здесь ключи.

- Выпуск SOV: commit `<полный SHA закреплённого выпуска>`;
  неизменяемый checkout `<абсолютный путь к checkout SOV>`.
- Основная копия проекта: `<абсолютный путь к основной копии>`;
  общий каталог состояния: `<абсолютный путь к основной копии>/.sov`.
  Все worktree используют этот каталог, не создают свою `.sov/`.
- Источник задач: файловый протокол через `sov-tasks` из закреплённого выпуска.
  Бинарник: `<абсолютный путь к bin-dir>/sov-task`.
  Из основной копии и worktree используй один `--state-dir`:
  `"<абсолютный путь к bin-dir>/sov-task" --state-dir "<абсолютный путь к основной копии>/.sov" validate`.
  Карточки, захват и завершение веди через `sov-tasks`, не правь хранилище вручную.
- OpenCode: `skills.paths` → `<абсолютный путь к checkout SOV>/skills`;
  проектные команды → `<абсолютный путь к основной копии>/.opencode/commands/`;
  проектные субагенты → `<абсолютный путь к основной копии>/.opencode/agents/`.
  `sov-standard` → `<настроенная модель standard>`,
  `sov-advanced` → `<настроенная модель advanced>`.

Перед установкой или обновлением сверяй эти сведения с фактическими ресурсами и конфигурацией;
при расхождении или недоступном файле остановись и уточни подключение.
При обновлении следуй `sov-update` и инструкции закреплённого выпуска;
операционные пути к CLI и общей `.sov/`, правила проверок и публикации проекта
находятся в `rules/`.
