# SOV

SOV — набор взаимосвязанных Agent Skills и шаблонов артефактов для разработки с агентами в OpenCode. Принципы работы описаны в [спецификации](docs/sov-spec.md), действующий файловый учёт — в [SOV Tasks](docs/specs/filesystem-tasks.md).

## Агенту, устанавливающему SOV в проект

Установка или обновление подключения — отдельное поручение для конкретного проекта. Сначала прочитай его `AGENTS.md`, `rules/index.md`, `docs/index.md` и применимые требования, затем [спецификацию SOV](docs/sov-spec.md) и [пошаговую инструкцию первой установки и обновления](docs/install-filesystem-tasks.md). Для поручения обновить установленный выпуск используй [скил `sov-update`](skills/sov-update/SKILL.md) вместе с [процедурой обновления](docs/install-filesystem-tasks.md#обновление-действующего-подключения). Для точки входа проекта есть [адаптируемый шаблон `AGENTS.md`](templates/AGENTS.md), для локальных сведений об установке — [отдельный образец](templates/installation.md); [порядок бережной правки](docs/install-filesystem-tasks.md#проектный-agentsmd) сохраняет существующие правила проекта.

При установке и ручном обновлении проверь локальную `<основная копия проекта>/.sov/installation.md`: закреплённый commit и пути выпуска SOV, `skills.paths`, проектные команды и субагентов OpenCode, бинарник `sov-task` и общий каталог `.sov/`. В опубликованных правилах проекта оставь операционные абсолютные пути к бинарнику и общему состоянию, доступные также из worktree. При обычном `/sov` оркестратор использует эти правила без чтения записи установки. Видимость команды сама по себе не означает, что проект подключён; для прежней установки без локальной записи сверяй существующие инструкции до перехода. Публикация этого репозитория работающие сеансы не обновляет.

SOV активируется только командами `/sov*`; обычный запрос (в том числе «используй SOV», правка файла, commit или push) выполняется по правилам целевого проекта без workflow SOV.
